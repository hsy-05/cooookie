| 資料夾           | 目的                            |
| -------------    | -------------------------------|
| app/Helpers      | 「工具型邏輯」，不屬於 MVC 任一層  |
| app/Listeners    | 「事件發生後要做的事」           |
| app/Providers    | 「整個系統的初始化與設定」       |



專案架構說明（app 資料夾）

==================================================

app/Helpers

檔案：ContentHelper.php

【目前功能】

儲存資料時，將完整 URL 轉換為 [[SITE_URL]] 標記

顯示資料時，將 [[SITE_URL]] 標記還原為實際完整 URL

顯示提示訊息頁面（例如成功 / 失敗提示）

【存在目的】

將多個 Controller 會用到的共用邏輯集中

避免在 Controller 中重複撰寫相同程式碼

【實務優點】

Controller 結構較乾淨

URL 轉換邏輯集中管理

【目前問題（專業角度）】

同時負責「資料處理」與「畫面顯示」，責任混雜

若專案成長，容易變成萬用 Helper，不利維護

檔案：ImageHelper.php

【目前功能】

圖片裁切、縮圖、補背景等處理

產生唯一圖片檔名

將處理後的圖片編碼並儲存到指定路徑

刪除圖片檔案（支援單筆與批次）

【存在目的】

集中處理圖片相關複雜邏輯

避免 Controller 過度肥大

【實務優點】

圖片處理邏輯可重用

降低圖片相關 bug 產生機率

【目前問題（專業角度）】

功能範圍偏大，未來容易持續堆疊功能

名稱為 Helper，但實際上已具備明確業務意義

檔案：SummernoteImageHelper.php

【目前功能】

比對舊內容與新內容中的圖片 URL

刪除舊內容中存在但新內容中不存在的圖片檔案

從 HTML 內容中擷取 <img src="...">，僅限指定 storage 路徑

【存在目的】

Summernote 編輯器圖片有特殊生命週期

避免圖片檔案殘留造成垃圾資料

【實務優點】

與一般圖片處理邏輯分離

可避免大量無用圖片累積

【目前問題（專業角度）】

已屬於明確業務邏輯，不適合長期放在 Helper

==================================================

app/Listeners

檔案：LogSuccessfulLogin.php

【目前功能】

監聽 Laravel 登入成功事件

登入完成後執行額外處理（如記錄登入行為）

【存在目的】

將「登入」與「登入後行為」分離

符合事件導向設計（Event / Listener）

【實務優點】

Controller 保持單一責任

後續擴充登入後行為不影響原本邏輯

【專業評價】

符合 Laravel 官方建議寫法

在面試與 Code Review 中屬於加分項目

==================================================

app/Providers

檔案：AppServiceProvider.php

【目前功能】

註冊應用程式層級服務

系統啟動時執行的初始化設定

【存在目的】

集中管理全系統共用設定

【專業評價】

正常使用方式

不建議放入任何業務邏輯

檔案：RouteServiceProvider.php

【目前功能】

設定使用者登入後的預設導向路徑

Route 相關行為設定

【存在目的】

集中管理 Route 的預設行為

【專業評價】

標準 Laravel 架構

無需特別調整

==================================================

app/Traits

檔案：Loggable.php

【目前功能】

在 Model 啟動（boot）時自動執行

實際寫入資料庫的 Log 紀錄

【存在目的】

多個 Model 共用相同行為（記錄操作 Log）

避免在每個 Model 重複撰寫 boot 邏輯

【實務優點】

減少重複程式碼

Model 行為一致化

【目前問題（專業角度）】

Trait 容易被濫用，塞入過多邏輯

若直接在 Trait 內操作 DB，除錯與測試困難

【專業建議】

Trait 僅負責「掛事件」

實際寫入 Log 應交由 Service 處理
